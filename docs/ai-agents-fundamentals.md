## Intro to AI Agents

- 智能体（Agent）与传统工作流（Workflow）的关键区别是什么？
- 工作流是预先确定并由开发者设计的，具有固定的路径，根据变量以确定性方式执行。而智能体则在运行时通过推理和工具决定其路径，路径在执行前是未知的。由 LLM 掌控决定采取哪个方向，而不是遵循预先设计的流程。



- 智能体循环的核心组成部分是什么？
- 智能体循环包括：1) 接收任务，2) 推理该做什么，3) 选择并执行工具，4) 观察结果，5) 判断是否有足够的信息来回答。该循环会重复进行，直到智能体拥有足够的上下文来提供最终答案。



- 为什么智能体不适合成功标准模糊的任务？
- LLM 使用强化学习进行训练，这意味着它们是在实现特定目标的基础上训练的。如果目标或成功标准不明确，智能体将无法良好执行，并会浪费计算资源（消耗大量 token）。明确的成功标准对于智能体有效运作至关重要。



- 智能体最大的失败模式之一是什么？
- 最大的失败模式之一是智能体自信地执行错误操作，却没有意识到自己犯了错误。智能体认为自己已成功并正确完成了所请求的任务，而实际上它所做的与预期不同。这种偏差可能源于指令不清晰、上下文不足或智能体自身能力的局限。



- 智能体不擅长哪些类型的任务？
- 智能体不适合：需要物理存在的任务（尽管随着机器人技术的发展，这种情况正在改变）、没有人工监督的高风险决策、需要人类品味的创造性工作（因为 LLM 只能重新组合训练数据）、成功标准模糊的任务、实时或对延迟敏感的操作，以及需要真正推理、上下文意识和常识且难以编码的任务。



## Create an Agent with OpenAI SDK

- 在 LLM 的语境中，什么是系统提示？
- 系统提示是 LLM 的基础指令，为它预先设定背景和指令。例如，它可能包含这样的指令：“你是一个有用的 AI 系统。你提供清晰、准确且简洁的回答。” 这为 LLM 应如何回应用户查询设定了上下文和行为。



- AI SDK 的提供商适配器模块（如 `@ai-sdk/openai` ）有什么用途？
- 提供商适配器模块允许你在使用相同 SDK 接口的同时切换不同的模型提供商（如 OpenAI、Anthropic 等）。这提供了灵活性，使你无需重写代码即可更换 LLM 提供商。



- 在最基本的层面上，LLM 工作原理的核心概念是什么？
- 从本质上讲，LLM 很简单：你给它一些文本（输入），它就会生成一些文本（输出）作为响应。复杂性在于构建能够进行对话、执行任务并持续产出良好结果的精密智能体。



## What is Tool Calling?

- LLM 的主要局限性是什么，导致它们无法回答关于近期事件的问题？
- LLM 的训练数据仅截至某个特定日期（即其训练截止日期），由于安全检查，这一日期通常比用户获得该模型访问权限的时间早近一年。它们无法访问或提供在其训练截止日期之后发生的事件的信息。



- 在 LLM 的语境中，什么是工具调用？
- 工具调用是允许 LLM 与外部世界交互的机制。它使 LLM 能够执行函数并访问外部资源，从而使其适用于需要最新信息或与系统交互的任务。



- 为函数调用定义工具需要哪三个主要组件？
- 三个主要组件是：1) 对工具功能以及 LLM 应在何时使用该工具的说明，2) 描述函数输入/参数的 schema，3) execute 函数——即工具被选中时实际调用的函数。



- 当 LLM 决定使用工具时，这个过程是如何运作的？
- LLM 实际上并不自己运行函数。相反，它会返回一个对象，描述它想要调用哪个工具以及想要传递的参数。随后系统使用提供的参数执行该工具，捕获结果，并将结果反馈给 LLM，以便它能够查看结果并决定下一步该做什么。



- 为了让编码智能体有效运作，它需要访问哪些类型的工具？
- 编码智能体需要访问能够让它执行以下操作的工具：读取、写入、更新和删除文件；搜索互联网；以及在终端中执行命令。如果没有这些工具，编码智能体就无法履行其职能。

## Understanding Evals

为什么我们需要评估？

评估（evals）对 AI 智能体开发至关重要，原因如下：

1. 智能体具有非确定性：相同的输入可能产生不同的输出，这使得传统测试不足以应对
2. 质量回归：模型更新、提示词更改或工具修改可能会悄无声息地降低性能
3. 部署信心：在发布更改之前，你需要可量化的指标
4. 调试：当出现问题时，你需要理解智能体为何做出某些决策

没有评估，你就是在盲飞。

你可能会根据几次手动测试就认为你的智能体运行良好，但在生产环境中，它可能会以你从未预料到的方式失败。
